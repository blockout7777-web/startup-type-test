Supabase에 profiles 테이블 만들기

⚠️ RLS(Row Level Security)를 반드시 비활성화하세요.
테이블 구조 (Supabase에서 직접 만드세요)
테이블명: profiles 칼럼 구성: • id — int8, Primary Key (자동 생성) • name — text (이름) • title — text (직함) • company — text (회사명) • bio — text (한 줄 소개) • phone — text (전화번호) • email — text (이메일) • address — text (주소 — 없으면 비워 두기) • sns_url — text (SNS 링크) ⚠️ RLS → 반드시 OFF ⚠️ 행은 딱 1개만 — 내 정보 한 줄
⚠️ 행은 반드시 1개만 넣으세요. 내 명함 정보 한 줄입니다. 여러 행을 넣으면 "어떤 명함을 보여줄지" 로직이 복잡해집니다.

⭐ 프로필 영역 — DB 연동의 첫 순간

이 단계가 오늘의 첫 번째 하이라이트입니다.
Supabase에 넣어둔 이름, 직함, 소개가 화면에 나타납니다.
프로필 사진이 있으면 images 폴더에 넣고 경로를 알려주세요.
프롬프트
프로필 영역을 Supabase 데이터로 채워 줘. 무엇을: 1. profiles 테이블의 첫 번째 행에서 name, title, company, bio를 읽어와 표시해 줘 2. 이름은 가장 크고 굵은 글씨로 3. 직함과 회사명은 이름 아래에 한 줄로 4. 한 줄 소개는 그 아래 회색 글씨로 5. 프로필 사진은 images/profile.jpg 파일을 원형으로 표시 (사진 파일이 없으면 이 줄을 지우세요) 어디를: 명함 카드 맨 위 프로필 구역 성공 기준: 1. Supabase에 넣은 내 이름이 화면에 가장 크게 보인다 2. 직함과 회사명이 이름 바로 아래 보인다 3. 한 줄 소개가 읽힌다 4. (사진이 있다면) 프로필 사진이 둥글게 표시된다
💡 사진이 없어도 괜찮습니다. 5번 줄을 지우고 보내면 됩니다. 사진 대신 이름 첫 글자를 원형 안에 넣는 이니셜 스타일도 나중에 지시할 수 있습니다.

⭐ 연락 버튼 3종 — 진짜 눌러서 확인

전화 · 이메일 · SNS 버튼을 만들고, 진짜 눌러서 작동하는지 확인합니다.
연결 안 되는 버튼은 가짜 문입니다. 가짜 문이 있는 명함은 신뢰를 깎습니다.
프롬프트
연락 버튼 3개를 만들어 줘. 무엇을: 1. 📞 전화하기 버튼 — profiles 테이블의 phone 값으로 tel: 링크를 걸어 줘. 누르면 전화 앱이 열려야 해 2. ✉️ 메일 보내기 버튼 — email 값으로 mailto: 링크를 걸어 줘. 누르면 메일 앱이 열려야 해 3. 📱 SNS 버튼 — sns_url 값으로 새 탭에서 열리게 해 줘 세 버튼은 가로로 나란히 배치하고, 각 버튼에 아이콘(이모지)과 짧은 텍스트를 넣어 줘. 버튼 색은 서로 다르게 해서 구분이 되게 해 줘. 어디를: 한 줄 소개 아래, 연락 버튼 구역 성공 기준: 1. 전화 버튼을 누르면 전화 앱에 번호가 뜬다 2. 메일 버튼을 누르면 메일 앱에 주소가 들어간다 3. SNS 버튼을 누르면 해당 페이지가 새 탭에서 열린다 4. 세 버튼이 시각적으로 구분된다
⚠️ PC에서 전화 버튼은 안 될 수 있습니다. tel: 링크는 폰에서만 전화 앱이 열립니다. PC에서 안 되는 건 정상이에요. 세션 4에서 폰으로 최종 확인합니다. mailto: 링크는 PC에서도 메일 앱이 열려야 합니다.

명함 하단에 QR코드를 생성합니다. QR코드의 본질은 URL이 들어 있는 사각형입니다.

프롬프트

⭐ QR코드를 실제 URL로 교체 — 세 번째 하이라이트

지금 QR에는 localhost URL이 들어 있습니다. 배포된 진짜 URL로 바꿔야 합니다.
프롬프트
QR코드의 URL을 배포 주소로 바꿔 줘. 무엇을: QR코드가 가리키는 URL을 아래 주소로 변경해 줘. 현재 window.location.href로 되어 있다면 고정 URL 문자열로 바꿔 줘. 새 URL: 여기에_Netlify_배포_URL_붙여넣기 QR코드 아래에 표시되는 URL 텍스트도 같이 바꿔 줘. 어디를: QR코드 생성 부분 성공 기준: 1. QR코드를 폰 카메라로 스캔하면 배포된 명함이 열린다 2. QR 아래에 배포 URL이 텍스트로 보인다
⚠️ URL을 바꾼 후 반드시 다시 배포하세요! 코드를 수정했으니 Netlify에 폴더를 한 번 더 끌어다 놓아야 합니다. 같은 사이트에 Deploys 탭 → 하단 드래그 영역으로 업데이트하세요.

서로의 명함 스캔하기

옆 사람의 QR코드를 스캔해서 명함을 열어 봅니다.
상대방 Supabase에 조회수가 올라간 것을 함께 확인합니다.
이것이 실제 네트워킹 현장에서 일어나는 흐름과 같습니다.

✓ 최종 체크리스트

  • Supabase에 profiles, views 두 테이블이 있다
  • 이름·직함·소개가 DB에서 불러와져 표시된다
  • 전화 버튼을 폰에서 누르면 전화 앱이 열린다
  • 이메일 버튼을 누르면 메일 앱이 열린다
  • SNS 링크를 누르면 해당 페이지가 열린다
  • QR코드를 스캔하면 배포된 명함이 열린다
  • 조회수 카운터가 올라간다
  • 모바일 폭에서 명함이 온전하게 보인다
  • 7문항 시험지에서 '못 씀' 0건이다
  • 모든 연락처가 실제와 한 글자도 다르지 않다

막혔을 때 쓰는 프롬프트

막힘은 실패가 아니라 실습의 일부입니다. 에러 메시지를 그대로 복사해서 붙여넣으세요.

A

DB에서 내 정보가 안 나올 때

프롬프트
Supabase profiles 테이블에서 내 정보를 불러오는데 화면에 이름이 안 나타나. 브라우저 콘솔(F12) 에러: (여기에 에러 메시지를 그대로 붙여넣기) 확인할 것: 1. URL과 KEY가 맞는지 2. 테이블 이름이 profiles가 맞는지 3. 칼럼 이름(name, title 등)이 맞는지 4. RLS가 꺼져 있는지 순서대로 확인하는 방법을 알려 줘.
B

QR코드가 안 보일 때

프롬프트
QR코드 영역이 빈 상자로 보여. 브라우저 콘솔 에러: (여기에 에러 메시지를 그대로 붙여넣기) qrcode.js 라이브러리가 로드됐는지, QR을 그리는 div의 id가 맞는지 확인하는 방법을 알려 줘. 코드는 아직 고치지 마.
C

조회수가 안 올라갈 때

프롬프트
새로고침해도 조회수가 0에서 안 올라가. Supabase views 테이블에도 행이 추가되지 않아. 브라우저 콘솔 에러: (여기에 에러 메시지를 그대로 붙여넣기) views 테이블 INSERT가 실패하는 원인을 찾아 줘. RLS 문제인지, 칼럼 구조 문제인지 확인 순서를 알려 줘.
D

QR 스캔이 안 될 때

프롬프트
폰으로 QR코드를 스캔했는데 명함 페이지가 안 열려. 확인해 줘: 1. QR코드에 들어 있는 URL이 Netlify 배포 주소가 맞는지 (localhost가 아닌지) 2. Netlify 사이트가 정상 작동하는지 3. 코드를 수정한 후 다시 배포를 했는지 현재 QR에 들어 있는 URL을 console.log로 출력하는 코드를 추가해서 확인하게 도와 줘.
💡 QR 스캔 방법 아이폰은 기본 카메라 앱으로 QR 인식이 됩니다. 안드로이드는 카메라 앱에 따라 다르므로, 안 되면 구글 렌즈 또는 네이버 앱의 스캔 기능을 쓰세요.
E

화면이 완전히 백지가 됐을 때

프롬프트
방금 지시 뒤에 화면이 완전히 백지가 됐어. 브라우저 콘솔(F12) 에러 메시지는 이거야: (여기에 에러 메시지를 그대로 붙여넣기) 원인 후보 세 가지와 확인 순서를 알려 줘. 파일은 아직 고치지 마.
