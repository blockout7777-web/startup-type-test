01 무엇을 만드나요?

12개의 질문에 답하면 4가지 창업가 유형 중 하나를 알려주는 심리테스트 웹서비스입니다.

4가지 결과 유형

💡 IDEA · 아이디어 탐험가 🚀 ACTION · 실행 돌격대장 📊 DATA · 데이터 전략가 🤝 PEOPLE · 관계 연결자

완성되면 이런 흐름이 됩니다

  • 닉네임 입력 → 테스트 시작
  • 질문 12개 → 선택지를 고르면 자동으로 다음 질문 (진행률 표시)
  • 결과 화면 → 내 유형, 강점, 주의할 점, 추천 창업 역할, 점수 막대그래프
  • 자동 저장 → 결과가 데이터베이스에 쌓임
  • 관리자 페이지 → 전체 참여자 통계를 한눈에

최종 결과물 (파일 6개)

파일역할누가 보나요
index.html테스트 화면 구조참여자 누구나
style.css디자인 (색·글꼴·배치)
script.js질문·점수 계산·DB 저장
admin.html관리자 화면 구조운영자만
admin.css대시보드 디자인
admin.js통계 집계·CSV 저장
왜 파일을 나누나요? 집을 지을 때 뼈대(HTML) · 인테리어(CSS) · 전기배선(JS)을 나누는 것과 같습니다. 나중에 색만 바꾸고 싶을 때 CSS 파일만 열면 되니까요.

03 무료 데이터베이스 준비

참여자 결과를 저장할 창고를 만듭니다. 4단계 프롬프트 전에 미리 해두세요.

① 프로젝트 만들기

  • supabase.com 로그인 → New Project
  • 이름은 아무거나, 비밀번호는 따로 메모해 두세요.
  • 지역은 Northeast Asia (Seoul)을 고르면 조금 더 빠릅니다.
  • 만들어지는 데 1~2분 걸립니다.

② 표(테이블) 만들기

왼쪽 메뉴에서 SQL Editor를 열고 아래를 붙여넣은 뒤 RUN을 누르세요.

SQL — 복사해서 SQL Editor에 붙여넣기 
-- 참여자 결과를 저장할 표를 만듭니다
create table test_results (
  id           bigint generated by default as identity primary key,
  nickname     text,
  result_type  text,
  idea_score   int,
  action_score int,
  data_score   int,
  people_score int,
  created_at   timestamptz default now()
);

-- 보안 기능을 켭니다
alter table test_results enable row level security;

-- 누구나 '결과 저장'은 할 수 있게 허용
create policy "누구나 결과 저장 가능"
  on test_results for insert
  to anon
  with check (true);

-- 통계를 보여주려면 '읽기'도 허용해야 합니다
create policy "누구나 통계 조회 가능"
  on test_results for select
  to anon
  using (true);

③ 연결 주소와 키 찾기

  • Project Settings → API 메뉴로 들어갑니다.
  • Project URL을 복사해 둡니다. (https://○○○.supabase.co)
  • anon public 키를 복사해 둡니다. (아주 긴 문자열)
  • 4단계 프롬프트 후 script.js 맨 위에 이 두 개를 붙여넣습니다.
⚠️ service_role 키는 절대 쓰지 마세요. 같은 화면에 service_role 이라는 키도 보이는데, 이건 데이터를 전부 지울 수 있는 관리자 열쇠입니다. 웹페이지에 넣으면 누구나 볼 수 있게 됩니다. 반드시 anon public 키만 사용하세요.

04 프롬프트 8단계 실습

순서가 중요합니다. 위에서부터 하나씩 복사해 AI에게 넣고, 결과를 확인한 뒤 다음으로 넘어가세요. 한 번에 여러 개를 넣으면 AI가 앞의 요청을 놓칠 수 있습니다.

1기본 테스트 만들기

파일 3개를 만들고, 질문 12개와 결과 화면이 동작하는 상태까지 한 번에 완성합니다.

PROMPT 1
VS Code에서 실행할 수 있는 웹페이지를 만들어줘.

프로젝트명은 "나는 어떤 창업가일까?"야.

HTML, CSS, JavaScript만 사용하고
index.html, style.css, script.js 3개의 파일로 분리해줘.

사용자가 12개의 질문에 답하면 다음 4가지 창업 유형 중 하나가 나오도록 만들어줘.

1. IDEA — 아이디어 탐험가
2. ACTION — 실행 돌격대장
3. DATA — 데이터 전략가
4. PEOPLE — 관계 연결자

조건:
- 첫 화면에 제목과 간단한 설명 표시
- 닉네임 입력칸 만들기
- "테스트 시작" 버튼 만들기
- 질문은 한 화면에 하나씩 표시
- 각 질문마다 선택지 4개 제공
- 선택하면 다음 질문으로 자동 이동
- 현재 질문 번호와 진행률 표시
- 총 12문항
- 가장 높은 점수 유형을 결과로 표시
- 결과에는 유형명, 설명, 강점, 주의점, 추천 역할 표시
- 모바일에서도 보기 좋게 반응형으로 제작
- 밝고 전문적인 스타트업 서비스 스타일
- 초보자가 이해할 수 있도록 중요한 JavaScript 부분에 한글 주석 추가

✅ 이렇게 되면 성공

  • 폴더에 index.html, style.css, script.js 3개가 생깁니다.
  • index.html에서 마우스 우클릭 → Open with Live Server로 열어봅니다.
  • 닉네임을 넣고 시작해 12문항을 끝까지 풀면 결과가 나옵니다.
이 프롬프트가 좋은 이유: ① 파일을 몇 개로 나눌지 ② 결과가 몇 가지인지 ③ 화면이 어떻게 동작해야 하는지를 구체적으로 못 박았습니다. "심리테스트 만들어줘"라고만 하면 매번 다른 결과가 나옵니다.
2질문과 점수 로직 점검

AI가 만든 질문이 공정한지 검사합니다. 특정 유형이 유리해지는 숨은 편향을 잡아냅니다.

PROMPT 2
현재 만든 창업가 유형 테스트의 질문과 점수 로직을 점검해줘.

다음 기준으로 수정해줘.

- 총 12문항 유지
- 각 문항은 정답이 없는 성향 질문
- 각 질문의 선택지 4개는 IDEA, ACTION, DATA, PEOPLE에 각각 1점씩 연결
- 질문 주제는 다음을 골고루 포함
  1. 아이디어가 생겼을 때 행동
  2. 사업에서 중요하게 생각하는 것
  3. 팀에서 맡는 역할
  4. 문제가 생겼을 때 행동
  5. 제품 출시 방식
  6. 경쟁자 대응
  7. 고객 불만 대응
  8. 새로운 기술 대응
  9. 투자금 활용
  10. 실패 가능성 대응
  11. 팀원 채용 기준
  12. 창업 성공 조건
- 특정 유형이 유리해 보이지 않도록 문장을 균형 있게 작성
- 선택 즉시 다음 질문으로 이동
- 마지막 질문 뒤에는 결과 화면 표시
- 기존 디자인은 최대한 유지

✅ 여기서 잡히는 문제

  • 위치 편향 — 12문항 모두 선택지 순서가 IDEA→ACTION→DATA→PEOPLE로 같으면, 사람들이 첫 번째를 더 고르는 습성 때문에 IDEA가 유리해집니다.
  • 동점 처리 — 유형당 1점씩이라 동점이 자주 나오는데, 항상 IDEA가 뽑히면 불공정합니다.
  • AI가 선택지 순서를 문항마다 섞어주고, 동점 규칙도 다시 만들어 줍니다.
실습 포인트: AI가 만든 결과를 그대로 믿지 않고 검사하는 것이 바이브코딩의 핵심입니다. "점검해줘"라는 한마디가 품질을 크게 바꿉니다.
3결과 화면 완성도 높이기

결과 화면에 담을 내용을 항목별로 지정해, 보고 싶은 정보가 빠짐없이 나오게 합니다.

PROMPT 3
현재 테스트의 결과 화면을 더 완성도 있게 개선해줘.

각 유형마다 다음 내용을 보여줘.

IDEA — 아이디어 탐험가
ACTION — 실행 돌격대장
DATA — 데이터 전략가
PEOPLE — 관계 연결자

결과 화면 구성:
- 유형 이모지 또는 간단한 아이콘
- 유형명
- 한 줄 설명
- 강점 3~4개
- 주의할 점 1~2개
- 추천 창업 역할
- IDEA, ACTION, DATA, PEOPLE의 점수를 막대 형태로 시각화
- "다시 테스트" 버튼
- 기존 테스트 기능은 변경하지 말 것
- 모바일에서도 보기 좋게 유지

✅ 이렇게 되면 성공

  • 유형마다 다른 이모지(💡🚀📊🤝)와 색상이 나타납니다.
  • 내 점수 4개가 막대그래프로 보입니다.
  • 강점·주의할 점·추천 역할이 목록으로 정리됩니다.
"기존 기능은 변경하지 말 것" — 이 한 줄이 아주 중요합니다. 이 말이 없으면 AI가 결과 화면을 고치면서 잘 돌아가던 질문 부분까지 건드릴 수 있습니다.
4무료 데이터베이스 연결

참여자가 테스트를 마치면 결과가 자동으로 Supabase에 저장되게 합니다.

PROMPT 4
현재 만든 창업가 유형 테스트에 Supabase 데이터베이스를 연결해줘.

Supabase JavaScript v2 CDN 방식을 사용해줘.

test_results 테이블에 다음 데이터를 저장해줘.

- nickname
- result_type
- idea_score
- action_score
- data_score
- people_score
- created_at

조건:
- 사용자가 테스트를 완료하면 결과를 Supabase에 저장
- 저장이 실패해도 결과 화면은 정상적으로 표시
- Supabase URL과 공개용 키는 script.js 상단에서 쉽게 수정하도록 작성
- URL과 Key를 입력할 위치에 한글 주석 표시
- 기존 테스트 기능과 디자인은 변경하지 않기
- 오류가 나면 console에 원인을 확인할 수 있도록 처리

✅ 이렇게 되면 성공

  • script.js 맨 위에 URL·키를 넣는 자리가 생깁니다. → 03단계에서 복사해둔 값을 넣으세요.
  • 테스트를 한 번 풀고 Supabase의 Table Editor를 열면 내 결과가 한 줄 들어와 있습니다.
  • F12 → Console 탭에 [Supabase] 저장 성공 ✅이 보입니다.
"저장이 실패해도 결과 화면은 정상적으로 표시" — 인터넷이 끊기거나 DB에 문제가 생겨도 참여자 화면은 멀쩡해야 합니다. 실제 서비스에서 아주 중요한 원칙입니다.
5전체 참여자 통계 넣기

저장만 하는 게 아니라 읽어오기까지. 결과 화면에서 전체 통계를 보여줍니다.

PROMPT 5
Supabase의 test_results 데이터를 읽어서 결과 화면 아래에 전체 참여자의 창업가 유형 통계를 추가해줘.

조건:
- IDEA, ACTION, DATA, PEOPLE 각각의 참여 인원 계산
- 전체 참여자 수 표시
- 유형별 비율(%) 계산
- 막대그래프로 표시
- 참여 인원이 0명이어도 오류가 나지 않게 처리
- DB 데이터를 불러오지 못하면 "통계를 불러올 수 없습니다." 표시
- 테스트 결과 화면은 항상 정상적으로 유지
- 기존 기능은 삭제하지 않기

✅ 이렇게 되면 성공

  • 결과 화면 아래에 "지금까지 총 ○명이 참여했어요"가 뜹니다.
  • 유형별 비율 막대가 나오고, 내 유형은 진하게 표시됩니다.
  • 옆 사람과 서로 테스트해보면 숫자가 실시간으로 올라갑니다.
"0명이어도 오류가 나지 않게" 를 꼭 넣으세요. 첫 참여자일 때 0으로 나누기가 발생해 화면이 NaN%로 깨지는 일이 흔합니다.
6디자인 다듬기

기능은 그대로 두고 보기 좋게만 바꿉니다. 기능과 디자인 작업을 분리하는 연습입니다.

PROMPT 6
현재 웹페이지의 기능은 절대 수정하지 말고 디자인만 개선해줘.

디자인 방향:
- 밝고 신뢰감 있는 스타트업 서비스 느낌
- 배경은 밝은 아이보리 또는 연한 회색
- 보라색 또는 파란색을 포인트 컬러로 사용
- 카드 모서리는 둥글게
- 버튼은 크고 명확하게
- 버튼 hover 효과 추가
- 질문 카드와 결과 카드를 구분
- 결과 유형별로 다른 이모지 사용
- 스마트폰에서도 버튼과 글자가 잘 보이도록 반응형 유지
- 너무 화려한 애니메이션은 사용하지 않기

✅ 이렇게 되면 성공

  • style.css 파일 하나만 바뀝니다. (기능 파일은 그대로)
  • 버튼에 마우스를 올리면 색이 진해지고 살짝 떠오릅니다.
  • 질문 카드는 보라색 띠, 결과 카드는 유형별 색상 띠로 구분됩니다.
색을 바꿔보세요: style.css 맨 위 --primary 값만 바꾸면 버튼·강조색이 한 번에 바뀝니다. 나만의 브랜드 색을 넣어보세요.
7배포 전 전체 점검

사람들에게 공개하기 전, 놓친 오류가 없는지 AI에게 항목별로 검사시킵니다.

PROMPT 7
현재 프로젝트를 배포하기 전에 전체 코드를 점검해줘.

점검 항목:
1. index.html, style.css, script.js 연결 오류
2. 테스트 시작 버튼 정상 작동
3. 12개 질문 정상 진행
4. 점수 계산 오류 여부
5. 결과 유형 정상 표시
6. Supabase 저장 성공 여부
7. Supabase 통계 조회 정상 작동
8. 모바일 화면 깨짐 여부
9. JavaScript 콘솔 오류 여부
10. GitHub Pages 같은 정적 호스팅에서 실행 가능한 구조인지 확인

문제가 있다면 수정해주고,
무엇을 수정했는지 초보자도 알 수 있도록 간단히 설명해줘.

✅ 실제로 이런 버그가 잡혔습니다

  • 선택지를 빨리 두 번 누르면 질문이 건너뛰어짐 — Q1에서 두 번 클릭하면 Q2를 건너뛰고 Q3으로 갔습니다.
  • 마지막 문항에서 두 번 누르면 DB에 2번 저장 — 참여자 수가 부풀려집니다.
  • 스마트폰에서 손가락이 두 번 닿으면 바로 생기는 문제라, 발견 못 했다면 수업 중에 터졌을 겁니다.
점검 항목을 번호로 나열한 게 핵심입니다. "점검해줘"만 하면 대충 훑고 끝나지만, 10개 항목을 못 박으면 하나씩 실제로 확인합니다.
8관리자 페이지 만들기

운영자만 보는 통계 대시보드를 별도 페이지로 분리합니다.

PROMPT 8
통계를 별도 관리자 페이지로 만들어줘

✅ 이렇게 되면 성공

  • admin.html, admin.css, admin.js 3개가 새로 생깁니다.
  • 비밀번호를 넣고 들어가면 전체 참여자 · 오늘 참여자 · 최다 유형 요약 카드가 보입니다.
  • 최근 7일 참여 추이 그래프와 참여자 목록 표가 나옵니다.
  • CSV 저장 버튼으로 엑셀에서 열어볼 수 있습니다.
짧은 프롬프트도 괜찮습니다. 앞의 7단계에서 맥락이 충분히 쌓였기 때문에 한 줄만으로도 AI가 알아서 만들어냅니다. 처음부터 이렇게 짧게 시작하면 안 되지만, 대화가 이어질수록 프롬프트는 짧아져도 됩니다.

05 인터넷에 배포하기

GitHub Pages를 쓰면 무료로 전 세계 어디서나 접속되는 주소가 생깁니다.

  1. github.com → New repository → 이름 입력 → Public 선택 → Create
  2. uploading an existing file 링크를 눌러 만든 파일들을 통째로 끌어다 놓기
  3. Commit changes 클릭
  4. 저장소 상단 Settings → Pages 이동
  5. Source를 Deploy from a branch, 브랜치를 main / /(root)로 설정 후 Save
  6. 1~2분 뒤 새로고침하면 주소가 나타납니다 → https://아이디.github.io/저장소이름/
주소를 QR코드로 만들어보세요. 네이버 QR코드 등에 주소를 넣으면 QR이 나옵니다. 수업에서 화면에 띄우고 다 함께 스캔하면 참여자 수가 실시간으로 올라가는 걸 볼 수 있습니다.
파일 이름을 반드시 소문자로. 인터넷 서버는 Index.html과 index.html을 다른 파일로 봅니다. 내 컴퓨터에서 잘 되던 게 배포하면 안 되는 가장 흔한 원인입니다.

06 문제가 생겼을 때

먼저 F12를 눌러 Console 탭을 확인하세요. 대부분의 원인이 여기에 적혀 있습니다.

증상원인해결
화면이 하얗게 나옴 파일 이름이 다르거나 같은 폴더에 없음 3개 파일이 같은 폴더에 있는지, 이름이 정확한지 확인
디자인이 안 먹힘 style.css 이름 오타 HTML의 href="style.css"와 실제 파일명 대조
저장이 안 됨 RLS 정책 미설정 03단계 SQL의 insert 정책을 실행했는지 확인
"통계를 불러올 수 없습니다" 읽기 정책 미설정 03단계 SQL의 select 정책을 실행했는지 확인
키를 넣었는데 안 됨 URL 끝 슬래시, 키 앞뒤 공백 따옴표 안에 정확히 붙여넣었는지 확인
통계 숫자가 NaN 참여자 0명일 때 0으로 나눔 AI에게 "0명일 때도 오류 안 나게 고쳐줘"
배포 후에만 안 됨 파일명 대소문자 전부 소문자로 통일 후 다시 업로드

AI에게 오류를 물어보는 요령

오류 해결 프롬프트 틀
지금 이런 문제가 생겼어.

[증상] 여기에 무슨 일이 일어나는지 그대로 적기
[내가 한 행동] 어떤 버튼을 눌렀을 때 생기는지
[콘솔 메시지] F12 → Console 탭에 나온 빨간 글씨를 그대로 복사해서 붙여넣기

원인을 찾아서 고쳐주고, 왜 그런 문제가 생겼는지 초보자도 알 수 있게 설명해줘.
"안 돼요"라고만 하면 AI도 못 고칩니다. 콘솔의 빨간 글씨를 그대로 복사해서 붙여넣는 것만으로 해결 확률이 크게 올라갑니다.

07 꼭 알아야 할 보안

실습용으로는 문제없지만, 진짜 서비스로 키울 계획이라면 반드시 알아야 할 3가지입니다.

① anon 키는 공개되는 게 정상입니다

웹페이지에 넣은 anon public 키는 누구나 볼 수 있습니다. 이건 잘못된 게 아니라 원래 그런 용도의 키입니다. 진짜 보호는 키를 숨기는 게 아니라 Supabase의 RLS 정책으로 합니다.

② 관리자 비밀번호는 진짜 자물쇠가 아닙니다

admin.js에 적힌 비밀번호는 파일을 열어보면 그대로 보입니다. 우연히 들어오는 사람을 막는 정도로만 생각하세요. 가장 간단한 해결책은 admin 파일 3개를 배포하지 않고 내 컴퓨터에서만 여는 것입니다.

③ 읽기 권한을 열면 닉네임도 공개됩니다

통계를 보여주려고 select 정책을 열면, 기술을 아는 사람은 참여자 닉네임 목록도 볼 수 있습니다. 수업 실습에서는 괜찮지만, 실명이나 개인정보는 절대 입력받지 마세요.

수업 후 정리: 수업이 끝나고 링크를 계속 열어둘 계획이 아니라면, Supabase 프로젝트를 일시정지(Pause) 하거나 anon 키를 재발급해 두는 것이 안전합니다.
